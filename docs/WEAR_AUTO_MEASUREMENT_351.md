# #351 Background recording, permission and fallback

- API 30–32: no separate background body sensor permission. API 33–35: BODY_SENSORS_BACKGROUND. API 36+: READ_HEALTH_DATA_IN_BACKGROUND.
- Ask the background grant separately, only after the heart-rate grant and only in response to the existing explicit measurement action. The optional explanation is shown once per permission; user can later change it in system app settings. No GPS background permission or automatic consent.
- Phone sends /trainpilot/measurement-start-351 to the single reachable matching companion. Schema 1: workoutId, minimum revision, owner epoch, send time; 15s lifetime, 2s future-clock tolerance. Configuration comes from the matching accepted canonical snapshot, not an arbitrary remote command. A missing/out-of-order snapshot falls back to the existing remote Activity. No ownership transfer. This is intentionally transient, not a queued command.
- Background attempt is currently limited to strength/non-GPS with heart sensor access, no known provider-location requirement. Cardio/GPS or missing grant use visible fallback. Existing ExerciseClient runtime capabilities and foreign exercise protections remain in place.
- Foreground service restrictions are distinct from sensor permissions. Message delivery is not a documented exemption. If start is denied, report foregroundRequired; never use alarm/overlay/other bypass. Existing service acknowledgement remains authoritative.
- System permission references: https://developer.android.com/health-and-fitness/health-services/background-body-sensors ; https://developer.android.com/health-and-fitness/health-services/permissions ; https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start
- Release checklist: verify policy/declarations for new health background grant and installer allowlisting. Physical Wear OS API 33–35 and 36+ grant/deny/revoke, app visible/background, locked screen, FGS denied, GPS fallback, repeated request, foreign app in progress, close during start. This change does not establish a guaranteed FGS exemption on paired Wear OS devices; no physical test result yet.
