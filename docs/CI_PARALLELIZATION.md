# Parallel CI and combined integration

The five independent full checks are phone JVM, Wear/shared JVM, app R8, Wear R8, phone D8. A sixth, brief aggregation job downloads only current-run artifacts, checks both checked-out commit markers and runs the unchanged raw XML verifier for all modules; both shard conclusions must be success. Full mode requires zero skipped tests, including main. Existing manual targeted filters remain; targeted jobs cannot satisfy automatic release admission because R8/D8 are skipped. The persistent signing workflow's trusted main SHA validation now demands all five checks plus the aggregate. It retains the separate full signing JVM gate and the existing paired APK/AAB build, signer pins, hashes and staged publication.

Baseline measured on modern run 46072173882: R8 440s, JVM 345s, D8 270s. Profile shows phone release Kotlin 158.78s, phone R8 118.88s, phone KSP 31.448s. The same runner cannot finish faster simply by adding tasks, and runner concurrency/queue times can reduce benefit. No guaranteed 4–5 minute result. Existing Gradle configuration/build caches, 4 workers, 2 phone forks and in-process compiler retained, without persistent configuration cache secrets. Phone/Wear APK+AAB are still built together to share release intermediates; signing is never run on PR branches.
